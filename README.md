# 神々の系譜 — 参拝アプリの体験デモ

**御朱印を「集める」から、貴方が「整う」。** 神社を探し、ご祭神を学び、御朱印写真と、その場所で生まれた誓い・感謝・気づきを残す日本語のWebアプリです。同梱の**デモ開発指示書 v1.0**の機能に、利用者が指定した「神道×マインドセット」の体験を追加しています。要件仕様書 v1.1 の正式版機能とは区別し、元の2冊の仕様書は変更していません。

- 公開サイト：<https://kamigaminokeifu.netlify.app/>
- 心の記録：<https://kamigaminokeifu.netlify.app/mind>
- ロードマップ：<https://kamigaminokeifu.netlify.app/roadmap>

## 心の記録を試す

1. ホームまたは下部の **心の記録** から「心の記録を書く」を開きます。寺社の詳細や御朱印の詳細からも、その場所を選択した状態で開けます。
2. 日付、寺社または日常、感謝の実感（1〜5）を選び、感謝・誓い・気づきのどれかを一言入力して保存。日常で踏み出す一歩も残せます。
3. タイムラインの「誓いを振り返る」から、現在地を「育てている／一歩進んだ／実践できた」に更新。実践の感想を追記できます。
4. 感謝のグラフは、記録がある最新14日分の日別平均。記録のない日は0にせず、数値表も併記します。自己評価であり、信仰や成長の採点ではありません。
5. 御朱印帳またはマイページから **心の成長ロードマップ** へ。10「知る」、22「深める」、33「定着化」、50「覚醒」の内容を選択して読み、50の画面では価値観・貢献・これからの宣言を下書き保存できます。

達成数は**御朱印を登録した異なる寺社の数**です。同じ寺社の複数写真は1か所、心の記録と参拝ボタンは加算しません。写真削除・寺社変更に応じて再計算します。寺社マスターのID単位なので、別項目として収録された内宮・外宮は各1か所です。現在は26寺社（実在6・架空20）のため33・50に実際には達成できず、**解放前のプレビュー**として体験できます。サンプル写真・架空寺社もデモ集計に含みます。心の記録と宣言の下書きは達成前から利用できます。

旧版の写真・ノート・ポイントを保持する追加移行を実装しています。心の記録と宣言もIndexedDBに保存し、交流ひろばには投稿しません。特定の人物による監修・推薦を表示していません。

## 開発・ビルド

Node.js **24.19.0 LTS**、npmを使用します（`.nvmrc`・Netlify・今回の実行環境で同じNode版）。通常の開発端末ではNode 24をインストールしてください。

```bash
cd /Users/U/Developer/kamigami-demo
# nvmを使っている場合
nvm install
nvm use
npm ci
npm run dev       # http://127.0.0.1:5173/
npm test          # 業務処理・IndexedDB・画像エラーの自動テスト
npm run build     # TypeScript検査 + Vite → dist
npm run preview   # http://127.0.0.1:4173/
npm run test:e2e  # Google Chromeが必要。独立したテスト用プロファイルで実行
```

このMacは通常のPATHにNode/npmがなかったため、今回の作業にはCodexの同梱Nodeと作業用npmを使用しました。`start-local.command` はNodeがPATHにない場合、このMacの同梱Nodeを利用します。他の端末は通常のNode/npmを用意してください。秘密鍵や外部APIキーは不要です。

## 最初に試す5つの操作

1. **マイページ → ミッション**で3つの企画に参加し、**探す**で「イセジンジャ」と検索。伊勢神社をお気に入りにして「デモ参拝を記録」。
2. 寺社詳細の**天照大御神**を開き、関係図・関連神社を確認。「学習を記録」とご祭神ノートの保存を試す。
3. **御朱印帳 → 御朱印を追加**でサンプル「伊勢神社」を選び、授与日不明のまま保存。寺社別・年月別・図鑑で確認し、写真の寺社や日付を修正する。
4. **ミッション**で達成ポイントを受け取り、**特典**で「朝の杜を歩く、文化案内」をデモ交換。キャンセルすると一度だけ返還される。
5. **マイページ**で住所のテスト例を変更・削除。続けて**運営体験モード**でイベントを公開し、**ホーム → 開催イベント**から申込・参加券・キャンセルを試す。

### データの扱い

すべての個人記録は**同じ端末・同じブラウザのIndexedDB**に保存されます。ブラウザデータを削除すると失われます。別端末・別ドメインへの引き継ぎやクラウド同期はありません。共用端末では同じブラウザを開いた人が閲覧できます。

住所は選択式のテスト例だけを扱い、URL、交流投稿、エラーログ、地図の出発地に自動出力しません。外部地図に渡すのは寺社名と寺社所在地です。本人認証や暗号化サーバー保存を実装したとは扱いません。

## 保存と業務処理の構造

- `src/data/`：寺社／神様マスター、ポイント設定、初期データ
- `src/services/storage.ts`：`Repository`インターフェース。構造化データと写真の2ストアを同一IndexedDBトランザクションで更新
- `src/services/domain.ts`：ポイント・ミッション・交換・返還・予約のルール。Reactから分離
- `src/services/address.ts`：`AddressMatcher`。保存済みのテスト例から同期照合し、旧住所の非同期結果が復活する経路を作らない
- `src/services/photos.ts`：`PhotoProcessor`。実写真の形式検査・縮小と、既知サンプルの整理を分離
- `src/services/mind.ts`：異なる寺社数・節目・日別自己評価・入力検証と心の記録の更新
- `src/pages/`：日本語画面。運営は独立した遅延読込画面

ポイントの正本は台帳です。達成ID・交換要求ID・返還IDを一意に扱い、同じ処理の再送を抑止します。残高・在庫・申込を同時に更新し、途中失敗はロールバックします。複数タブもIndexedDBの書込トランザクションで直列化し、BroadcastChannelで再読込を促します。写真削除後も報酬の台帳は保持されます。
